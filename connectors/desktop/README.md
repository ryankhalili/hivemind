# Desktop connector

On Windows, open `HiveMind-Setup.exe`. It installs a per-user copy under LocalAppData/HiveMind and a Start menu shortcut. No administrator access is needed. The first build is unsigned. Keep the window open while using the connector.

In the dashboard, create a pairing code under Devices. Enter your server address, that code, and a folder in the desktop window. Only that folder is shared. Pairing is remembered locally; future connections do not need a new code. Revoke a lost device in the dashboard.

In Devices, choose an approval level for that folder: ask for every action, allow routine reads, or allow reads and creation of new files. This choice lasts until you change it, disconnect, or share a different folder. Folder access does not permit overwriting or deleting files. Commands, agents, and browser actions always need a separate approval. The connector identifies the folder without sending its full path to the server; replacing that directory or choosing a different one requires reviewing access again.

By default the connector supports device information, directory listing, UTF-8 text reads (up to 64 KB), and creation of new text files (up to 64 KB). File tools reject absolute paths, parent traversal, symbolic links, Windows junctions, unknown tools, and overwrites. Your local operating-system account must be trusted; this is not a sandbox against another malicious local process changing files concurrently.

In Access, you can enable commands and choose whether sensitive actions need a second confirmation on this computer. Register agent harnesses in Agents. These permissions start disabled. Every process needs approval in the dashboard. By default a second confirmation on this computer shows its complete command or goal, with a 60-second countdown. If it expires, the action is cancelled without starting. You can enable “Accept command and agent approvals from HiveMind” on this computer to approve remotely without that second prompt. The server cannot turn this setting on. Use it only with a server you trust. A process runs as your operating-system account and can access files and network resources outside the shared folder. Setting its working directory does not sandbox it.

`command.run` accepts `{argv:["executable","argument"],cwd:".",timeout:120}`. Arguments stay separate and no command shell is inserted. Batch files require the user to request an explicit interpreter. Working directories must be inside the shared folder. Timeouts range from 1 to 300 seconds. Combined stdout and stderr are limited to 16 KB; excess output is drained and discarded. A nonzero exit code marks the task failed.

`harness.run` accepts `{harness_id:"custom",goal:"...",context:{},cwd:".",timeout:120}`. Register the executable and fixed argument list locally using the file chooser. The server can select an advertised harness ID and supply a goal, but cannot change the registered executable or its arguments. Custom adapters receive one JSON object on standard input: `{version:1,goal:"...",context:{}}`. They may return JSON on stdout or ordinary text. A Python adapter can be registered by selecting python.exe and setting fixed arguments to `["C:/path/to/adapter.py"]`. Future PC, browser, or other agent engines can use this same interface.

At connection time the adapter configuration is copied and fingerprinted. Its public manifest contains a SHA256 revision, without executable paths. The revision covers executable contents, fixed arguments, and explicitly configured script files. Before execution, including after local confirmation, the connector checks that fingerprint again. A change requires reconnecting and renewing the dashboard's permissions. This does not fingerprint every imported package or protect against a hostile process using the same OS account.

If Hermes is already installed, an optional toggle registers its CLI. It runs a fresh non-interactive request with terminal tools, at most eight turns, and the same five-minute maximum. It does not use `--yolo`, accept hooks automatically, or resume an existing chat. Its local credential setup remains under Hermes. The full goal needs dashboard approval and follows the local confirmation setting. Other custom harnesses may have broader powers; only register software you trust.

Heartbeats continue while a process is running or waiting for local confirmation. Only the currently executing task and its lease are advertised as active; idle heartbeats do not keep old claims alive. Cancellation, disconnect, and timeout stop the process tree using a Windows Job Object with taskkill fallback, or a Unix process group. Previous side effects are not undone. The connector acknowledges `cancelled` only after stopping the process. If the network remains unavailable, it stops local work after repeated heartbeat failures; the server may report an uncertain outcome until it receives the acknowledgment.

Each received task ID is recorded on disk before execution. Lost acknowledgments never cause an action to run twice. If the connector crashes during an action, the server must report an uncertain outcome rather than assume failure and retry. Cancellation is checked before bounded file operations; a completed write cannot be cancelled retroactively.

Reconnect after sleep or temporary network loss works while the app is open. Optional checkboxes enable reconnect on launch and opening at sign-in. Windows uses a per-user Run entry; macOS uses a per-user LaunchAgent and copies the source launcher into Application Support. Neither option is enabled automatically. Changes take effect after connecting.

Disconnect stops local work, revokes the saved credential on the server, and removes the local token. The device disappears from the available device list and requires a new pairing code to reconnect. Server and folder preferences may remain. If the server cannot be reached, the app says that disconnect is pending, disables automatic reconnection and the Connect button, and preserves the credential only to retry revocation. Press Retry disconnect when online. An in-flight pairing request must finish before revocation, so a late credential cannot leave a newly registered device active.

Closing the window only pauses this app and retains pairing; it does not revoke the device. Forget device performs the same server revocation as Disconnect and also clears local preferences and startup registration. A device whose pairing response was lost should be removed from the dashboard if no token is available locally.

The Mac ZIP contains this app and a double-clickable launcher. It requires Python 3 with Tkinter, available in the python.org macOS installer. It is an early source launcher, not a signed native Mac installer. Linux users can run `python3 app.py` with Tk installed. Android and iOS currently use the web dashboard; no native device-control app is included.

Server addresses require HTTPS except on localhost. The connector refuses redirects so bearer credentials never move to another host. Credentials stay in the local per-user application directory; do not copy connection.json into source control.

For developers, `node.py` separates transport, folder operations, a durable execution journal, and the polling loop. Add future capabilities behind explicit scopes and approval rules. Preserve the at-most-once execution behavior.
